RAG 的两条链路：离线索引和在线问答

RAG包含离线索引与在线问答两条链路，检索质量和生成质量必须分开测量。

不少 RAG 原型的架构图只有三块：文档、向量库、大模型。接入以后回答仍然不准，团队就开始换向量数据库。可一条回答真正经过的环节远比这三块多，任何一处都可能丢失信息。

先分开两条链路

离线索引流负责读取文档、解析格式、切分内容、生成嵌入、写入索引，并保存来源与权限元数据。在线问答流负责理解问题、必要时改写查询、检索候选、排序、组装上下文、调用模型，再验证引用和输出安全。

向量数据库只承担其中一部分。文档解析错了，表格结构已经丢失；切分太碎，上下文不完整；切分太大，又召回一堆无关内容；查询改写偏离原意，后面模型再强也拿不到正确证据。RAG 的上限，首先由送到模型之前的信息链路决定。

分开测检索和生成

回答错误时，先问两个问题：正确证据有没有被找回来？模型拿到正确证据后有没有据此回答？前者用召回率、排序质量和权限过滤评估，后者看接地性、完整性、引用准确性与拒答。

Google Cloud 的 RAG 参考架构把数据摄取与在线服务分开。Rogo 的客户案例同时介绍了检索链路和模型评测。文中报告的幻觉率下降来自其模型对比，检索环节的独立效果需要另做评估。

引用不是装饰

企业知识问答还要把来源、时间和权限带到最后。用户看到引用，系统也要保证引用确实支持结论，而不是随便附上一条相似文档。找不到足够证据时，应明确拒答或转人工，不能让模型用常识补齐内部事实。

所以排查 RAG 时，最好保存每一步中间结果：原始查询、改写查询、候选片段、排序分数、最终上下文和回答。链路透明，问题才有可能被定位。

还要建立一组“应该找不到”的问题。很多评估只检查有答案的样本，结果系统学会了无论如何都给出内容。对企业知识助理而言，越权问题、过期资料和知识库没有覆盖的问题同样重要。能否拒绝、能否指出缺少什么证据、能否正确转到人工，是 RAG 质量的一部分，也是在真实环境里控制幻觉的关键。

评估还要覆盖同义问法和多轮追问，防止系统只记住固定题面。对于跨文档问题，要检查证据组合过程，而不能因为最终答案碰巧正确，就忽略引用不完整或权限过滤失效。

核心要点

  1. 把 RAG 拆成离线索引流和在线问答流。

  2. 逐项检查解析、切分、嵌入、检索、排序和上下文组装。

  3. 分开评估检索质量与生成质量。

  4. 让来源、时间和权限随证据进入回答。

  5. 证据不足时拒答，不要让模型自由补齐企业事实。
